<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Python/API writers to PostgreSQL trigger | Any insert into `pipeline_events` causes trigger execution. |
| PostgreSQL NOTIFY to Node listener | Notification payload text crosses into API process and is parsed as JSON. |
| Listener helper to route callback | Parsed identifiers wake route code that will re-query canonical rows. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-05 | I | `notify_pipeline_event()` | mitigate | Notify only `job_id` and `event_id`; migration tests and grep criteria reject `metadata` in notification SQL. |
| T-02-06 | T | notification payload parser | mitigate | Validate parsed `job_id` and `event_id` are strings before invoking callback; malformed payload tests prove callback is not called. |
| T-02-07 | D | listener client lifecycle | mitigate | `close()` always attempts `UNLISTEN pipeline_events` and `end()`; tests assert cleanup calls happen once. |
| T-02-08 | S | listener wake-up | accept | Notifications are not authorization decisions; route-level API key remains the access control boundary and live delivery re-queries by the authenticated route's job id. |
</threat_model>
