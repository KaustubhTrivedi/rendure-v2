<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client to SSE stream | Untrusted clients can hold long-lived HTTP connections. |
| PostgreSQL notification to route flush | Database notification payload influences when the route queries. |
| pipeline_events metadata to SSE response | Stored metadata may include operational details and is sent to authenticated clients. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-09 | S | `GET /jobs/:id/events` | mitigate | Preserve inherited `/jobs/*` API key middleware and keep app-level auth test in final suite. |
| T-02-10 | T | live cursor SQL | mitigate | Use fixed SQL strings with `$1`, `$2`, `$3` parameters for job id, timestamp, and event id; tests inspect query parameter arrays for live flushes. |
| T-02-11 | D | long-lived streams | mitigate | Add 30-second keepalive, abort cleanup, terminal close, interval clearing, and listener `close()` tests. |
| T-02-12 | I | sensitive metadata leakage | mitigate | Keep D-04 payload shape only for authenticated clients; do not include notification payload data, request headers, API keys, or environment variables in SSE frames; tests assert payload keys. |
| T-02-13 | R | stream failure observability | mitigate | Emit `event: stream_error` with `{"error":"Stream failed."}` when failure occurs after stream start, then close; no stack traces or SQL text are sent. |
</threat_model>
