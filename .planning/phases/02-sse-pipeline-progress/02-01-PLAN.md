<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client to Hono route | Untrusted HTTP method, path `:id`, and `Last-Event-ID` header enter the API process. |
| Hono route to PostgreSQL | Route values are used in SQL queries against `jobs` and `pipeline_events`. |
| PostgreSQL row to SSE client | Stored `pipeline_events.metadata` and `detail` are serialized to the client. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | S | `GET /jobs/:id/events` | mitigate | Rely on existing `app.use('/jobs/*', apiKeyMiddleware())`; test through `api/src/index.ts` that missing `X-API-Key` returns 401 for `/jobs/job-123/events`. |
| T-02-02 | T | `Last-Event-ID` and `:id` SQL usage | mitigate | Use only parameterized SQL with `$1`, `$2`, `$3`; tests assert query calls receive SQL plus params arrays, never interpolated strings. |
| T-02-03 | D | replay stream lifecycle | mitigate | Stop replay and return after terminal `to_status` values `approved`, `low_match`, or `error`; route tests prove terminal replay closes. |
| T-02-04 | I | SSE payload metadata | mitigate | Emit only the D-04 allowed row fields and exclude legacy `payload`; acceptance grep requires `toPipelineEventPayload` fields and no `created_at` alias. |
