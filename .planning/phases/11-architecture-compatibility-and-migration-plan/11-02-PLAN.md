<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SQL migrations to existing production data | New SQL can mutate or reinterpret existing pipeline data. |
| Application workflow state to pipeline state | Downstream application statuses could pollute pipeline lifecycle state. |
| Application timeline to pipeline audit | User workflow activity could be stored in pipeline audit rows. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-05 | Tampering | `database/008_compat_boundaries.sql` | mitigate | Static tests reject direct writes to trigger-owned `jobs.qa_score` and `jobs.iteration_count` per D-05. |
| T-11-06 | Tampering | `jobs.status` / `allowed_transitions` | mitigate | Tests assert application statuses are not pipeline statuses per D-04. |
| T-11-07 | Repudiation | `pipeline_events` vs `application_timeline_events` | mitigate | Separate application timeline table and tests preserve audit source boundaries per D-07. |
| T-11-08 | Information Disclosure | Timeline metadata | mitigate | Migration creates a separate metadata surface; later writers must use redaction guardrails from Plan 03/04 before storing private details. |
| T-11-SC | Tampering | npm/pip/cargo installs | accept | No package installs are planned; existing lockfiles remain unchanged. |
</threat_model>
