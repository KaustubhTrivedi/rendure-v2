<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Ashby API response["success"] → application flow control | Untrusted boolean from external server controls submission outcome |
| response["errors"] → DB error_detail | Untrusted error strings from Ashby written to DB |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-05-01 | Tampering | Ashby response["success"] field | mitigate | always read success field, never trust HTTP status alone; handle missing key gracefully |
| T-18-05-02 | Information Disclosure | response["errors"] written to error_detail | mitigate | truncate errors array to first 5 items; join as plain string; no nested objects |
| T-18-05-03 | Information Disclosure | PII in Ashby POST body | accept | Ashby is the intended recipient; no local logging of multipart body |
| T-18-05-04 | Denial of Service | Ashby API timeout | mitigate | httpx timeout=30s; single retry on 5xx only |
| T-18-05-SC | Tampering | No new package installs | accept | httpx already in codebase |
</threat_model>
