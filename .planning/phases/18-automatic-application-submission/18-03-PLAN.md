<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Greenhouse API response → application code | Untrusted JSON from external ATS; parse defensively |
| resume YAML DB → PDF bytes → multipart POST | Resume content leaves the system boundary |
| user_profile fields → multipart POST | PII (email, phone) transmitted to Greenhouse servers |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-03-01 | Spoofing | Greenhouse API response (fake candidate id) | mitigate | validate response["id"] presence; absent = silent-accept failure path |
| T-18-03-02 | Information Disclosure | PII in multipart POST to Greenhouse | accept | Greenhouse is the intended recipient; no logging of request body |
| T-18-03-03 | Information Disclosure | error_detail written to DB on failure | mitigate | truncate Greenhouse error response to first 500 chars; never log full response with potential redirect tokens |
| T-18-03-04 | Denial of Service | Greenhouse API timeout | mitigate | httpx timeout=30s on GET and POST; single retry on 5xx only |
| T-18-03-SC | Tampering | No new package installs | accept | httpx already in codebase (used by llm.py) |
</threat_model>
